# 测试反馈回流目录说明

## 目录作用
本目录用于AI测试Agent知识闭环，将自动化测试执行结果、发现的遗漏场景、历史缺陷回流到知识库，持续优化Agent的测试覆盖能力。

## 文件分类

### 1. uncovered_scenario.md（未覆盖场景）
#### 用途
记录测试过程中发现的、知识库中缺失的业务场景和分支。

#### 记录格式
```
## 场景编号：SC-001
### 场景描述
简要描述业务场景

### 发现来源
- 版本：V2.2.0.1
- 发现方式：手工测试 / 自动化执行 / 线上问题

### 涉及模块
- 模块名称

### 缺失原因
知识库哪个部分缺少该场景说明

### 补充建议
应该补充到哪个知识文档
```

#### 典型场景
- 边界条件场景
- 异常分支场景
- 多系统交互特殊场景
- 并发冲突场景

---

### 2. bug_history.md（历史缺陷库）
#### 用途
记录历史缺陷，供Agent生成测试用例时参考，避免同类问题重复出现。

#### 记录格式
```
## 缺陷编号：BUG-001
### 缺陷标题
简要描述缺陷

### 缺陷等级
严重 / 主要 / 次要 / 提示

### 业务模块
所属模块

### 触发条件
详细描述复现条件

### 根本原因
缺陷根因分析

### 修复版本
哪个版本修复

### 测试建议
针对此类问题的测试要点
```

#### 使用规则
- Agent生成测试用例时，必须参考历史缺陷，重点覆盖同类场景
- 相同根因的缺陷归类整理，提炼通用测试点
- 严重级别高的缺陷优先覆盖

---

### 3. automation_optimize.md（自动化优化记录）
#### 用途
记录自动化脚本执行不稳定点、需要优化的地方，以及框架改进建议。

#### 记录格式
```
## 优化项编号：OPT-001
### 优化点描述
简要描述需要优化的内容

### 问题现象
当前存在的问题

### 影响范围
影响哪些用例、哪些场景

### 优化方案
建议的优化方式

### 优先级
高 / 中 / 低
```

#### 常见优化项
- 元素定位不稳定
- 接口断言不准确
- 测试数据构造失败
- 环境依赖问题
- 执行速度慢
- 用例间互相干扰

---

## 回流工作流
### 触发时机
1. 每次版本测试完成后
2. 自动化执行发现失败用例后
3. 线上问题复盘后
4. 需求变更评审后

### 处理流程
```
发现问题 → 分类判断
    ├─ 业务场景缺失 → 写入 uncovered_scenario.md → 更新对应业务文档
    ├─ 缺陷根因 → 写入 bug_history.md → 补充对应测试点
    └─ 自动化问题 → 写入 automation_optimize.md → 优化脚本/框架
```

### Agent使用规则
1. 生成测试方案前，必须读取本目录所有文件
2. 历史缺陷对应的场景必须覆盖
3. 已知未覆盖场景必须纳入测试范围
4. 自动化优化点在生成脚本时需规避

## 维护要求
- 每月定期整理，去重合并
- 已补充到主知识库的场景，从uncovered_scenario移除
- 已修复且长期稳定的缺陷，可归档处理
- 优先级高的优化项优先处理
